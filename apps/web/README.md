# Web 模块（A：场景配置 / B：3D 与回放 / E：统一入口）

B 负责 3D 场馆、2D 俯视、热力、示意粒子、时间轴和比较展示；A 负责场景配置；E 协调统一入口。当前 A 的编辑功能与 E 的入口尚未实现。

## B 的 W1 原型（BOOT-03，关联 REQ-03）

状态：W1 演示原型，待评审。技术栈尚未在 BOOT-08 锁定，因此本原型使用原生 ES Module + Three.js 0.169（本地 vendored 于 `prototype/lib/`，无构建步骤、无框架、无锁文件）；BOOT-08 确认 React + TypeScript 后再迁移。

### 已实现

- 读取 Mock 场馆与场结果（`examples/scene.mock.json`、`examples/field.mock.json`），并做契约一致性校验（维度、场景引用、source 标识、不可通行单元为零）
- 布局：3D 主视图占左侧主要区域，2D 俯视图、图例与契约自检集中于右侧栏，播放控制置于底部横栏（参考评审建议，未逐项照搬）
- 3D 场馆：半透明玻璃壳墙体（含描边）、障碍实体投影、出口地面高亮 + 边界门洞光片 + 标注，轨道相机与"透视 / 俯视 / 重置"视角预设
- 密度热力图随帧更新（3D 为角点插值的平滑热力面，2D 为逐单元网格，共用同一色标），帧间线性插值（仅用于播放演示）；配色为低-中-高连续渐变（初版浓郁色板 #264478 / #EBBE46 / #CD2D23；曾试用评审建议的柔和色板，因观感偏淡回退），超过警示阈值（暂定 3.0 人/m²，待 BOOT-06 与 D 确认）的单元向更亮的警示色过渡，图例在色标上标注阈值位置（Mock 数据最大 1.0 人/m²，不触发）
- 示意粒子跟随连续速度场，象牙白 + 深色描边，与热力图全色域保持明度对比、任意密度区域都清晰可辨（密度信息由地面色标承担）；带 ≤15% 局部流速的固定个体微扰，避免同一路径的粒子汇聚成理想直线；离开可通行区域按密度加权重新投放
- 时间轴（底部横栏）：播放 / 暂停 / 拖动 / 倍速 / 循环，滑块两端标注仿真时间范围；暂停时全场冻结，粒子不推进（热力与 2D 视图仍可随时间轴拖动和悬停刷新）
- 2D 俯视图：热力 + 出口高亮 + 速度箭头 + 坐标轴指示 + 单元悬停读数
- 图例：密度色标渐变条（0 – 全场最大密度）与出口 / 障碍 / 粒子样式
- 坐标方向自检：判定有速度的单元是否指向最近出口（不假设出口方位，可复用于真实场数据），结果在页面状态面板显示

### 运行

在仓库根目录（需要本地 HTTP 服务器，`fetch` 不支持 `file://`；Three.js 已本地化，无须联网）：

```powershell
python -m http.server 8000
# 浏览器打开 http://localhost:8000/apps/web/prototype/
```

建议使用 Chrome / Edge 等现代浏览器。

### 坐标映射约定（与 [契约](../../contracts/README.md) 一致）

- 计算平面 x/y，单位米；数组 `[iy][ix]`，行从 y 小到大；速度元素 `[vx, vy]`
- 网格原点是左下角单元的左下角，单元中心为 `origin + ((ix+0.5)*dx, (iy+0.5)*dy)`
- Three.js 渲染映射：`world = (x, height, -y)`；2D 俯视图直接按数据坐标绘制（y 向上）
- 页面状态面板的"方向自检"应显示 PASS；若热力 / 箭头 / 粒子方向与出口不符，说明映射写反

### 边界说明

- 页面顶部显著标注 Mock 数据；粒子数量与路径仅为示意，不代表真实人数，不构成个体疏散结论（NFR-04）
- W2 计划：将数据源从 Mock 切换为 C 输出的真实 PDE 场结果，并记录播放性能；方向自检与契约校验不依赖 Mock 的东向出口，可直接复用
