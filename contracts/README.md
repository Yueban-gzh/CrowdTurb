# CrowdTurb 数据契约草案

版本 `0.1.0`，状态为 W1 待评审提案。字段是仓库为提前联调新增的设计，不是原始材料已经确定的接口。正式采用前由 A/B/C/D/E 联合确认；尤其 PDE 边界和真实场文件布局仍需 C 确定。

## 场景与连续场

- [scene.schema.json](scene.schema.json)：小型规则网格、可通行掩码、初始密度、边界出口、允许调整的出口宽度及边界策略。
- [field-result.schema.json](field-result.schema.json)：帧时刻、密度、速度、场景引用与结果来源。当前仅支持小型内嵌数组，不承诺是正式生产格式。
- [task.schema.json](task.schema.json)：任务状态及结果 / 错误引用；只是任务对象，不代表 HTTP API 已实现。

例子见 [examples](../examples/README.md)。`tools/check_repository.py` 同时执行 JSON Schema 和跨字段语义检查；只调用 Schema 不会验证数组长度与网格大小的关系。

## 坐标与单位

计算平面为 x/y，长度米、时间秒、密度人/平方米、速度米/秒。网格原点是左下角单元的左下角，单元中心为 `origin + ((ix+0.5)*dx, (iy+0.5)*dy)`。

数组采用 `[iy][ix]`，每行从 x 小到大，行从 y 小到大；每个速度元素是 `[vx, vy]`。渲染层自行将计算平面映射到 3D，例如 Three.js 可用 `(x, height, -y)`；不能改变传输中的轴含义。A/B 首周用已知方向验证。

`walkable=false` 的单元密度与速度为零。掩码只表达草案栅格，不代替 A 的完整建筑几何、连通检查和精细出口表示。出口引用边界上的可通行单元；草案规定宽度上限为所引用单元的总边界长度，真实几何离散关系需 A/C 评审。

## 来源与复现

`source` 为 `mock`、`pde` 或 `fno`。当前仅有 `mock` 样例；它们是任意合成帧，不保证守恒或满足 PDE。真实结果记录实际提交、算法版本、环境、场景版本 / 文件 SHA-256 和求解配置；FNO 另记数据集、模型和训练划分。

`mock` 与真实结果不共享验收资格。正式运行不能用 `mock` 样例直接改标签获得真实身份；元数据校验也无法证明算法已真实执行。非 Mock 结果要求复现记录，但正确性与科学可信度仍靠实验。

## 任务状态提案

单次任务允许 `queued → running → succeeded / failed`，以及启动失败时 `queued → failed`。`succeeded` 必须有 `result_id`，`failed` 必须有 `error`；其余状态不携带结果或错误。`source` 是请求的计算来源，成功后必须与实际结果来源一致；失败可无结果。

当前未定义取消、重试和进度百分比。一次重试建议生成新的任务 ID，最终由 E 确定。静态 Schema 仅能验证单个状态快照，状态转换需未来服务测试验证。

## 首周必须补齐

- A/C：建筑矢量结构如何生成掩码，出口实际宽度如何离散，以及其他边界 / 初始条件是否足够表达。
- C/B/E：帧采样、输出时间范围、大数组存储与读取方式、速度场的空间位置定义。
- D/C：指标与出口通量结果结构、积分方法、阈值和质量误差容差。
- E：API 路由、项目 / 运行对象、任务持久化、错误分类和结果可用性。
- 全员：兼容策略与签署；变更同时更新 Schema、例子、语义检查及消费方。
