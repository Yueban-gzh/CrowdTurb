# ADR 0002 W1 系统底座临时技术边界

状态：提议，已按此实现 W1 验证原型；待 BOOT-08 团队评审后决定是否长期采用。

日期：2026-11-20
参与人：E（H-yuin）实现；A-D 尚未评审。
关联需求 / Issue：BOOT-08、BOOT-09、REQ-06、NFR-02。

## 背景与约束

仓库已有数据契约、Mock 样例和验证工具，但没有可启动服务。BOOT-08 尚未完成框架选型，不能让其他成员等待 E；同时 BOOT-09 需要真实 HTTP 边界、项目保存、任务状态和失败反馈。W1 的目标是形成可替换的集成骨架，而不是提前锁定 React / FastAPI。

## 候选方案与取舍

- Python 标准库 `http.server` + SQLite + 原生 HTML / CSS / JavaScript：无新增运行时依赖，当天可启动，适合验证状态机和持久化；代价是缺少生产级路由、认证、并发与静态资源缓存能力。
- FastAPI + React：长期更贴近候选技术栈，但需要先完成依赖、构建链、接口评审和开发环境统一，首周成本更高。
- 只做命令行脚本：可验证存储，但无法向 A-D 提供统一访问方式，也不能验证用户任务流。

## 决策及影响

W1 采用标准库 HTTP 边界、SQLite 和无需构建的静态页面。HTTP 层只负责请求解析与响应，`AppService`、`Store` 和求解适配器保持独立；A-D 依赖的是服务接口和契约，不是 `http.server`。如果 BOOT-08 选择 FastAPI，替换 HTTP 边界即可，不应改动任务状态机、持久化语义或结果契约。

Mock 适配器与 PDE / FNO 占位适配器显式分离。PDE / FNO 未接入时任务失败并返回 `solver_not_configured`，不能把 Mock 结果改标签冒充真实结果。

## 验证与后续

- 契约检查与 11 项契约回归通过。
- 8 项系统 API 测试覆盖项目 / 场景往返、Mock 成功、PDE 未接入失败、无效输入、重启持久化和中断任务恢复。
- 本决策不证明 PDE / FNO、3D、指标或布局优化可用，也不证明部署安全。
- 重新评估触发条件：BOOT-08 技术选型完成、第二种真实求解适配器接入、典型结果无法用 JSON 承载、需要多人并发或正式部署。
