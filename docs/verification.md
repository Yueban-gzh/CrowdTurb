# 验证与验收计划

现按 [ADR 0002](decisions/0002-stddn-trajectory-and-passage.md) 的 STDDN 路线修订，产品整体验收仍未执行。A/D 局部单元检查有记录，不能替代完整运行和验收；每人维护本模块测试，E 组织集成，结果更新 [需求追踪](traceability.json)。

## 已有检查的边界

`tools/check_repository.py` 验证 Schema、Mock 形状 / 单位 / 时间 / 引用、资料校验值和文档链接。`tests/contracts/` 检查负数密度、非有限值、坐标转置、障碍内状态、无效出口、版本错配和任务状态负载等联调错误。

这两项通过只证明仓库初始化产物可用，不代表已有 PDE、3D、保存或优化功能，也不代表 GitHub Actions 已运行。

## 产品用例

### VT-01 场景往返与合法性

负责人 A/E，关联 REQ-01。载入真实示例场馆，修改一个出口 / 通道与初始密度，保存后重启再打开，比较参数与版本。检查负密度、非法几何和不支持配置，确认错误可见且不会产生无效任务。

### VT-02 完整个体仿真基准

负责人 C，关联 REQ-02。以固定人员运行直通道、封闭区、出口、障碍和通道宽度变化。验证时间推进、有限状态、人数/事件收支、规划与碰撞、不穿墙和时间步敏感性。证明 A 新掩码被真实消费；单次 ONNX 调用或空轨迹不能作为完整仿真证据。

### VT-03 场到画面的映射

负责人 B，关联 REQ-03。手算小场检查坐标/时间/热力；接入 C 轨迹与 D 聚合场，验证 3D/俯视和回放，显示出口/设施/通道变化。真实轨迹、装饰性粒子和实测轨迹区分，不以粒子数作为人数。

### VT-04 指标手算与真实场核对

负责人 D，关联 REQ-04。先用固定人员手算轨迹验证网格人数/面积、平均速度、空格、热点与非等间隔左端积分；显式事件核对出口累计人数。检查人员消失、重复 ID/事件、越界/障碍、时间乱序和非有限输入均拒绝。随后对实际 C 轨迹核对人数收支和适用范围。

### VT-05 建筑候选与公平比较

负责人 D/A/C/E，关联 REQ-05。检查出口宽度、设施位置和通道宽度改变实际几何/掩码；保留非法、重复和未评价状态。用同一初始人员/位置/速度/行为属性、随机策略及模型/规划/碰撞配置实际运行；保留无改善结果和修改代价，不靠截图或几何通过声称优化有效。

### VT-06 完整任务与用户流程

负责人 E 组织全员，关联 REQ-06。从固定场馆开始，经统一入口配置、保存、计算、回放、诊断、候选和对比，演示中不改代码或手工换文件。检查任务排队 / 运行 / 成功 / 失败，失败有错误且不伪装成功。从新环境重启并复现关键结果。

### VT-07 模型适用性实验

负责人 C，关联 REQ-07。记录权重、训练/测试条件、适用范围和模型哈希；验证持续 rollout、拥挤/障碍/出口场景、失败样本和时间步。分别测量模型、邻居搜索、规划、碰撞与完整运行成本，不将 ETH/HOTEL 数据说明当作场馆验证。

### VT-08 模型与运行失败

负责人 C/E，关联 REQ-06、REQ-07。模型缺失、推理异常、路径失败、碰撞失效或轨迹不完整时，任务失败且保留原因，D 不输出伪造的成功指标。若提供替代模型，明确来源和验证条件，不静默标为 STDDN，也不假设存在 PDE 回退实现。

## 质量用例

### VT-09 复现实验

负责人 C/D/E，关联 NFR-01。记录代码提交、场景摘要、配置、环境、硬件和种子策略，按相同条件重复运行，使用预先定义的容差或波动统计比较。记录异常和不可复现部分。

### VT-10 契约与集成

负责人 E 协调全员，关联 NFR-02。先运行现有仓库契约检查，真实生产方 / 消费方实现后补充接口测试，包括未知版本、损坏结果、单位 / 形状错误及持久化失败。确认 Mock 替换真实结果不需要手工改页面代码。

### VT-11 性能与错误反馈

负责人 E/B/C，关联 NFR-03。W1 确定演示环境与测试方法，W2 实测后评审性能目标；测量求解等待、结果大小、加载与播放。包含失败任务和不可用输入的用户反馈，报告数值及边界，不先承诺帧率或秒数。

### VT-12 来源与结论审查

负责人 B/D/E，关联 NFR-04。检查 mock/stddn 标签、轨迹和装饰粒子、阈值来源与无改善结果。旧 PDE/FNO 文件保留历史来源；新聚合场不改名冒充 PDE。所有效果结论链接真实实验，不描述为安全认证。

## 结果记录

使用 [实验记录模板](templates/experiment.md) 保存真实执行记录、环境、参数、命令、预期与实测、结论和局限。小记录进入 `docs/evidence/`；大型原始输出在外部版本化存储，记录获取方式和摘要。追踪中的 `verified` 需有实际证据和验收评审，不能只凭文件存在。
