# 验证与验收计划

当前为计划，产品和算法用例均未执行。仓库检查仅验证草案契约和文档一致性，不能替代下列测试。每个负责人实现本模块用例，E 组织集成与用户任务验收；执行后更新 [需求追踪](traceability.json)。

## 已有检查的边界

`tools/check_repository.py` 验证 Schema、Mock 形状 / 单位 / 时间 / 引用、资料校验值和文档链接。`tests/contracts/` 检查负数密度、非有限值、坐标转置、障碍内状态、无效出口、版本错配和任务状态负载等联调错误。

这两项通过只证明仓库初始化产物可用，不代表已有 PDE、3D、保存或优化功能，也不代表 GitHub Actions 已运行。

## 产品用例

### VT-01 场景往返与合法性

负责人 A/E，关联 REQ-01。载入真实示例场馆，修改一个出口 / 通道与初始密度，保存后重启再打开，比较参数与版本。检查负密度、非法几何和不支持配置，确认错误可见且不会产生无效任务。

### VT-02 PDE 数值基准

负责人 C，关联 REQ-02。以明确初始 / 边界条件运行小型直通道、封闭域、出口和障碍基准；检查有限值、非负性、质量收支、障碍边界和网格 / 时间步敏感性。先由 C 记录公式、期望行为与数值容差，再运行；不能将“所有密度都为零”视为正常解。

### VT-03 场到画面的映射

负责人 B，关联 REQ-03。使用可手工判断方向和热点的小场检查轴、时间、热力色标；再接入真实 PDE 检查 3D / 俯视、播放 / 暂停及障碍处理。粒子应跟随场，界面不能把粒子数当作人数。

### VT-04 指标手算与真实场核对

负责人 D，关联 REQ-04。先确定连续场指标公式、积分方法、单位及阈值来源。手算小型均匀场、空场、单出口通量和已知热点，比较实现结果；随后将真实 PDE 密度积分与出口收支核对，并披露误差。

### VT-05 建筑候选与公平比较

负责人 D/A/C/E，关联 REQ-05。保存原方案与至少一个真实建筑参数变化的候选，检查约束和配置差异；在同等条件下实际求解。保留无改善与非法候选用例；核查排序所用指标、代价和结果来源，不能只展示最好截图。

### VT-06 完整任务与用户流程

负责人 E 组织全员，关联 REQ-06。从固定场馆开始，经统一入口配置、保存、计算、回放、诊断、候选和对比，演示中不改代码或手工换文件。检查任务排队 / 运行 / 成功 / 失败，失败有错误且不伪装成功。从新环境重启并复现关键结果。

### VT-07 FNO 实验

负责人 C，关联 REQ-07。记录数据生成和划分，控制泄漏；独立测试集报告适用场景、密度 / 速度误差、最坏样本和相同硬件下的时间。分别报告训练、加载与推理耗时。失败尝试如实留痕，不编造误差或加速倍数。

### VT-08 FNO 回退

负责人 C/E，关联 REQ-06、REQ-07。模型不存在或未达条件时，PDE 闭环仍可运行；结果来源保持真实。FNO 预测参与候选初筛时，最终展示的布局评价仍有真实 PDE 证据。

## 质量用例

### VT-09 复现实验

负责人 C/D/E，关联 NFR-01。记录代码提交、场景摘要、配置、环境、硬件和种子策略，按相同条件重复运行，使用预先定义的容差或波动统计比较。记录异常和不可复现部分。

### VT-10 契约与集成

负责人 E 协调全员，关联 NFR-02。先运行现有仓库契约检查，真实生产方 / 消费方实现后补充接口测试，包括未知版本、损坏结果、单位 / 形状错误及持久化失败。确认 Mock 替换真实结果不需要手工改页面代码。

### VT-11 性能与错误反馈

负责人 E/B/C，关联 NFR-03。W1 确定演示环境与测试方法，W2 实测后评审性能目标；测量求解等待、结果大小、加载与播放。包含失败任务和不可用输入的用户反馈，报告数值及边界，不先承诺帧率或秒数。

### VT-12 来源与结论审查

负责人 B/D/E，关联 NFR-04。检查界面和报告中的 Mock / PDE / FNO 标签、粒子说明、阈值依据及无改善结果；所有效果结论链接到真实实验。课程结果不能被描述为真实疏散安全验证。

## 结果记录

使用 [实验记录模板](templates/experiment.md) 保存真实执行记录、环境、参数、命令、预期与实测、结论和局限。小记录进入 `docs/evidence/`；大型原始输出在外部版本化存储，记录获取方式和摘要。追踪中的 `verified` 需有实际证据和验收评审，不能只凭文件存在。
