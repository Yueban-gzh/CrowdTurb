# CrowdTurb 合并原型

历史记录：以下为 2026-11-26 的快照联调。2026-11-27 已在 D/E 集成分支改为使用当前仓库模块，并支持 0.3 通道编辑；当前入口与实跑结果以 [D/E 集成证据](2026-11-27-DE-integration.md) 和 [联调接口](../workbench-interfaces.md) 为准。

启动后在同一个工作台编辑展厅、运行预演、查看 3D / 2D 回放和热力，再打开 D 的候选列表。每次保存完整场景与结果，运行记录可以重新打开。

## 启动

从仓库根目录执行。使用 Python 3.11 或 3.12。启动命令自动准备固定版本的模块，已有快照则直接复用。

```powershell
python -m pip install -r requirements-workbench.txt
python tools/start_workbench.py
```

打开 [工作台](http://127.0.0.1:8770/)。修改 E1 出口宽度或 F1 展台位置后点击「评估当前布局」。评估期间可刷新查询状态。显示新修订后，从「人流与热点」切换基准与推荐候选，在「方案比较」查看参数、指标及状态原因。

B 可从 [加载接口](../workbench-interfaces.md) 获取运行清单及产物。默认启动时为旧版 B 生成一次兼容页面，HTTP 服务随后原样提供该页面。B 实现原生加载后，用 `--native-viewer` 指向 B 的仓库根目录进行联测。

## 共享联调检查

GitHub Actions 的 `workbench-integration` 安装工作台依赖并下载启动脚本指定的 A/D 和 B 提交。Python 用例检查任务及产物，浏览器用例修改出口、提交异步评估、刷新同一个运行编号，并打开 D 的比较结果及 B 的基准和候选回放。

测试使用 Mock 轨迹。Windows 与 Ubuntu 的基础检查由原有矩阵运行。完整浏览器联调由 Ubuntu 上的 Chromium 运行。

## 联调发现

- **A/E：无修改也可能改变输入哈希。** Python 默认值含 `4.0`，浏览器输出 `4`，A 的哈希元数据直接序列化数值。本原型统一四个求解参数的数值表示，回归覆盖无改动时哈希稳定与改变出口后哈希更新。后续由 A/C/E 共同确认正式数值规范。
- **A/D：场景版本与初始化人口需要对齐。** A 网页编辑器支持 `0.2`，D 的通道案例是 `0.3`。旧 D 演示固定两名行人及起点，现由 E Mock 根据 A 的密度栅格生成初始人员。当前使用派生的 `0.2` 样例，通道可视编辑待 A/D 对齐版本。
- **B/D：回放与热力必须读同一次运行。** B 原入口写死本地数据集，轨迹模式自行聚合热力。合并版在 B 的加载入口按运行 ID 获取 A 的出口格、Mock 轨迹、D 聚合场及分析，出口、人员和热点共用同一网格和时间轴。
- **C：真实仿真入口待联调。** E 的 Mock 适配器输出合成轨迹和退出事件。接入真实短轨迹后，再安排同初始状态的基准与候选重新求解，并核对两侧各自的输入哈希。

模块源于 [D PR #3](https://github.com/Yueban-gzh/CrowdTurb/pull/3) 和 [B 分支](https://github.com/Yueban-gzh/CrowdTurb/tree/feat/B-w1-visualization) 的固定快照。桥接代码集中在 E，团队可以先用同一个运行版本复现问题。

本地验证：浏览器实际修改出口、生成修订 2，B 的数据自检通过，并切换了 2D、3D 和候选回放。使用 `CROWDTURB_TEAM_FIXTURES` 指向 D 快照，12 项系统用例与 11 项契约用例通过。
