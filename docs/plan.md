# 五人分工与四周迭代

周次从团队实际开工起计算，不根据仓库建立日期推断课程截止日。A–E 尚未绑定姓名。以下安排来自 V5 五人计划，仓库任务划分是便于执行的细化。

## 模块边界

- A：初始场配置，维护建筑、出入口、通道、初始密度与可调参数。向 B 提供建筑、向 C 提供输入、向 D 提供约束。
- B：3D 场馆、2D 俯视、热力、示意粒子、时间轴和比较展示。消费场数据，不重复实现核心求解。
- C：PDE 基准、FNO 数据 / 训练 / 推理与误差速度实验。统一向 B、D、E 输出连续场；FNO 不可用时保留 PDE。
- D：指标定义、热点、约束候选搜索、排序与公平比较。通过 E 执行任务，不自行绕过运行记录。
- E：项目骨架、持久化、任务和 API、联调、部署与整体验收。协调跨模块集成，不承包其余四人的核心功能。

每个负责人维护本模块测试，E 组织集成测试。跨模块接口由相关成员共同确认。

## W1 基础与契约

A 交付可用的场馆 / 初始场配置雏形；B 交付基于 Mock 的 3D 场馆、热力与粒子；C 启动 PDE 基线并明确 FNO 方案；D 明确指标和候选设计并在 Mock 上联调；E 搭建产品入口、保存与 Mock 任务接口。

共同验收：五人均有独立演示；评审场馆 / 场结果 / 指标契约；明确技术栈、公式、网格、单位、可调变量、性能测量方法和验收容差。首周任务见 [backlog](backlog.md)。

## W2 真实数据集成

A 完成基本编辑和几何检查；B 读取真实 PDE 并播放；C 稳定输出 PDE、生成 FNO 训练数据并训练初版；D 完成基础指标与候选搜索起步；E 调用真实计算并保存结果。

共同验收：同一场景经 E 调用 C，B 播放，D 计算基础指标；记录实测性能与仍缺失的测试。

## W3 完整业务闭环

A 输出真实变化的通道 / 出口配置；B 提供回放、指标面板和 A/B 页面；C 完成 PDE/FNO 推理对比；D 使用真实 PDE 评价候选；E 联通全流程。

共同验收：配置 → 求解 → 3D → 分析 → 候选 → 比较可以连续操作，包含无改善和失败情况。FNO 未达标不阻断闭环。

## W4 完善与交付

各模块修复异常并补足测试，B 优化交互和录屏，C 提交正确性与误差速度实验，D 整理比较结果和局限，E 组织从干净环境启动、部署、回归和整体验收。

共同交付：可运行原型、示例场馆、PDE/FNO 实验记录、3D 回放、指标与候选比较、启动说明、测试结果和演示材料。

## 跟踪方式

GitHub Milestone 建立 W1–W4；Issue 使用 `todo / in progress / review / done` 状态。标签建议 `module:A` 至 `module:E`、`requirement`、`bug`、`experiment`、`change`。未连接 GitHub 前可先维护 backlog 文件。

每周一次目标会、周中按需联调、周末全组 Demo，记录使用 [迭代模板](templates/iteration.md)。不按日历自动认定任务完成。
