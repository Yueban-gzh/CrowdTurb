# 五人分工与四周迭代

2026-11-25：四周结构保留，计算路线由用户确认为 STDDN，C 输出完整轨迹与退出事件，D 聚合场/指标并补通道宽度。以下涉及 PDE/FNO 的原计划条目按 [ADR 0002](decisions/0002-stddn-trajectory-and-passage.md) 替换执行；不因周次或已有模型文件自动认定完成。

周次从团队实际开工起计算，不根据仓库建立日期推断课程截止日。A–E 尚未绑定姓名。以下安排来自 V5 五人计划，仓库任务划分是便于执行的细化。

## 模块边界

- A：初始场配置，维护建筑、出入口、通道、初始密度与可调参数。向 B 提供建筑、向 C 提供输入、向 D 提供约束。
- B：3D 场馆、2D 俯视、热力、示意粒子、时间轴和比较展示。消费场数据，不重复实现核心求解。
- C：完整 STDDN 仿真、路径/碰撞/出入场、带 ID 轨迹和事件、模型适用性与性能实验。
- D：轨迹聚合、指标/热点、约束候选搜索、排序和公平比较；补通道宽度接口，通过 E 执行并保留记录。
- E：项目骨架、持久化、任务和 API、联调、部署与整体验收。协调跨模块集成，不承包其余四人的核心功能。

每个负责人维护本模块测试，E 组织集成测试。跨模块接口由相关成员共同确认。

## W1 基础与契约

A 交付场景/初始配置；B 演示 Mock 3D 并准备轨迹/聚合场接口；C 完整运行小型 STDDN 场景；D 手算验证聚合/指标并生成含通道的候选；E 准备任务与保存。

共同验收：五人均有独立演示；评审场馆 / 场结果 / 指标契约；明确技术栈、公式、网格、单位、可调变量、性能测量方法和验收容差。首周任务见 [backlog](backlog.md)。

## W2 真实数据集成

A 完成编辑、几何检查和通道 UI 适配；B 播放实际仿真结果；C 稳定输出轨迹并证明几何变化响应；D 接入真实轨迹与候选；E 执行并保存真实任务。

共同验收：同一场景经 E 调用 C，D 聚合并分析，B 播放；记录完整成本与缺失测试。

## W3 完整业务闭环

A 输出出口/设施/通道变化；B 提供回放、指标和比较；C 完成稳定性、适用性与性能实验；D 同条件评价真实候选；E 联通全流程。

共同验收：配置 → 仿真 → 聚合/分析 → 3D → 候选比较连续操作，包含无改善和失败；单次推理成功不算完整计算。

## W4 完善与交付

各模块修复异常并补足测试，B 优化交互和录屏，C 提交正确性与误差速度实验，D 整理比较结果和局限，E 组织从干净环境启动、部署、回归和整体验收。

共同交付：可运行原型、场馆、STDDN 适用性与完整仿真实验、轨迹/热力回放、指标及候选比较、测试和演示材料。

## 跟踪方式

GitHub Milestone 建立 W1–W4；Issue 使用 `todo / in progress / review / done` 状态。标签建议 `module:A` 至 `module:E`、`requirement`、`bug`、`experiment`、`change`。未连接 GitHub 前可先维护 backlog 文件。

每周一次目标会、周中按需联调、周末全组 Demo，记录使用 [迭代模板](templates/iteration.md)。不按日历自动认定任务完成。
