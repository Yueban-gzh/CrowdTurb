# 首周任务清单

初始状态均为待认领。以下本地编号在创建 GitHub Issue 时保留在标题或正文中；不是已经创建的远程 Issue。一个任务可拆分为多个小 PR。2026-11-20 的实际进展见任务下方状态说明。

## BOOT-01 需求与分工评审

负责人 E 组织，全员参加。关联 REQ-01–07、NFR-01–04。确认 A–E 姓名、四周起止、必做边界、FNO 实验与产品接入的区别。交付评审记录和基线修改 PR；不能用“已开会”替代实际记录。

## BOOT-02 场馆与设计变量

负责人 A。关联 REQ-01、REQ-05。选定单层体育馆，确定出口 / 通道中一个变量、可调范围、固定结构和几何校验规则。交付小型场馆样例及至少一个合法、一个非法配置测试。

## BOOT-03 可视化雏形

负责人 B。关联 REQ-03。读取共同 Mock 场馆和场结果，完成 3D 示例、俯视切换、热力与时间播放。验证坐标方向；显著标识 Mock，不推断真实人数。交付可演示页面和运行方式。

## BOOT-04 PDE 方法与基准

负责人 C。关联 REQ-02、NFR-01。调研并记录方程、边界、网格、稳定性约束和误差 / 守恒容差，跑通最小基准。交付 ADR、独立命令、真实场文件和正确性检查；仓库现有 Mock 不算 PDE 结果。

## BOOT-05 FNO 实验设计

负责人 C。关联 REQ-07。记录输入输出、数据生成预算、划分及泄漏防止、网络候选、硬件和误差速度测量办法。交付实验计划与回退条件；不要求首周交付训练完成的模型。

## BOOT-06 指标定义与手算验证

负责人 D。关联 REQ-04。明确残留人数、出口流量、拥堵持续量等的连续场公式、单位与阈值假设。用小场手算期望值并测试实现；说明 Mock 帧不保证守恒，不能据此计算真实效果。

## BOOT-07 候选与公平比较设计

负责人 D，与 A/C/E 共同评审。关联 REQ-05。确定候选生成、约束过滤、求解预算、排序和比较条件。交付一个参数真实变化的候选及合法性验证，不预设一定改善。

## BOOT-08 产品技术选型

负责人 E 协调，全员评审。关联 NFR-02、NFR-03。在熟悉程度、四周成本、3D 需求和算法运行环境之间作取舍。更新架构 ADR 状态；确定后再增加框架、锁文件和启动命令。

## BOOT-09 系统任务与保存雏形

负责人 E。关联 REQ-06。统一项目入口、场景保存和 Mock 任务；覆盖成功 / 失败状态。交付可启动服务和接口测试，数据来源明确。HTTP 路由与存储方案以第一周 ADR 为准。

状态：实现待评审（E / H-yuin，2026-11-20）。已交付系统 API、统一入口、SQLite 持久化、Mock 成功链路、PDE/FNO 未接入失败链路和 8 项系统测试；尚未提交 PR 或完成 A-D 联调，不计为已验收。

## BOOT-10 契约联合评审

负责人 E 协调 A/B/C/D。关联 NFR-01、NFR-02。检查草案字段是否足够表达 PDE 边界、建筑变量、时序和结果来源；落实大数组存储方式和任务错误格式。交付契约修改 PR，确保所有样例和检查通过。

## BOOT-11 GitHub 协作设置

负责人 E。关联 NFR-02。创建或连接团队仓库，邀请四名成员，建立 W1–W4，配置 `main` 保护和至少一人评审。仓库模板存在不代表远程规则已生效。

## BOOT-12 首周集成与风险复盘

负责人 E 组织，全员演示。关联所有必做需求。用同一示例展示各模块，更新 [追踪记录](traceability.json)、[风险](risks.md) 和下一周任务。保留失败项和阻塞，不把模块 Mock 演示当作整体验收。
